# Internationalization (i18n)

The site ships in three locales: Spanish (`es`, default), English (`en`), and Catalan (`ca`). This document captures the architecture decisions and the workflow for translating new copy.

---

## URL scheme

`prefixDefaultLocale: false` keeps Spanish at the root and prefixes the others:

| Locale | URL prefix | Example |
|---|---|---|
| `es` (default) | *(none)* | `/sobre`, `/detalle/ouroboros-descent` |
| `en` | `/en` | `/en/sobre`, `/en/detalle/ouroboros-descent` |
| `ca` | `/ca` | `/ca/sobre`, `/ca/detalle/ouroboros-descent` |

The `<html lang>` attribute on every rendered page matches the active locale (`html class="dark" lang="es"` on `/`, `lang="en"` on `/en/`, `lang="ca"` on `/ca/`).

---

## Source of truth

| Concern | Lives in | Notes |
|---|---|---|
| Astro i18n config | `astro.config.mjs` | `i18n.defaultLocale = "es"`, `i18n.locales = ["es", "en", "ca"]`. |
| UI translation strings | `src/i18n/{es,en,ca}.json` | Dot-notation. Loaded by `useTranslations()` from `src/lib/i18n.ts`. |
| `tattoos` content | `src/content/tattoos/<locale>/<slug>.md` | `locale` is also a frontmatter field. |
| `faq` content | `src/content/faq/{es,en,ca}.json` | Identical shape across locales. |
| `sobre` content | `src/content/sobre/{es,en,ca}.json` | Identical shape. |
| `site_settings` | `src/content/settings/{es,en,ca}.json` | Identical shape; only the strings differ. |

`site_settings` keeps non-translated fields identical across locales (`contact_email`, `instagram_url`, `whatsapp_number`, `address`). The `hero_*`, `about_short`, `tagline`, `location`, `brand_name` and `opening_hours` fields are translated.

## Page structure

Pages live in three sibling trees that share one rendering component:

```
src/pages/sobre.astro              ← ES wrapper, <SobrePage locale="es" />
src/pages/en/sobre.astro           ← EN wrapper, <SobrePage locale="en" />
src/pages/ca/sobre.astro           ← CA wrapper, <SobrePage locale="ca" />

src/components/pages/SobrePage.astro  ← renders everything; takes locale as prop
```

The same shape repeats for `index.astro`, `reserva.astro`, `faq.astro` and `detalle/[slug].astro`. The wrapper is intentionally tiny (one line, the component invocation) so duplication is invisible and the locale routing is always explicit.

Each wrapper renders a shared `<XxxPage locale="…" />` component from `src/components/pages/` that:

1. Reads `src/i18n/<locale>.json` via `useTranslations(locale)`.
2. Loads `site_settings`, `sobre`, or `faq` content for the locale (`getSiteSettings(locale)`, `getEntry("sobre", locale)`).
3. Sets `<html lang={locale}>` in `Layout.astro`.
4. Renders the same JSX, only swapped copy.

---

## URL plumbing

`src/lib/i18n.ts` exports:

- `useTranslations(locale) → t(key)` — dot-path lookup; returns the key itself when missing (so devs see a typo at runtime instead of an empty string).
- `getLocaleFromPath(pathname) → Locale` — extracts `/en/...`, `/ca/...`, or returns `es`.
- `localizePath(pathname, target) → string` — converts any pathname to its equivalent under a new locale, preserving the tail:
  - `localizePath("/sobre", "en")` → `"/en/sobre"`
  - `localizePath("/en/detalle/ouroboros-descent", "ca")` → `"/ca/detalle/ouroboros-descent"`
  - `localizePath("/en/detalle/ouroboros-descent", "es")` → `"/detalle/ouroboros-descent"` (default has no prefix)
- `stripLocale(pathname) → string` — strips an existing locale prefix from a path.

The language switcher in `TopBar.astro` uses these so the dropdown options always point to the same page in another language.

## Adding a new string

1. Open `src/i18n/es.json` and add the key under the appropriate section. Keep keys **full sentences**, never concatenate parts at render time:
   ```json
   "filosofia": {
     "title": "El Arte de la Marca Permanente"
   }
   ```
2. Add the same key to `en.json` and `ca.json` with idiomatic translations. Never literal word-for-word — the tone is editorial Spanish → clean modern English / Catalan, not Babelfish.
3. Read it from the component with `useTranslations(locale)`. Components import the helper and call it inside the frontmatter:
   ```astro
   ---
   import { useTranslations, DEFAULT_LOCALE } from "../lib/i18n";
   const locale = (Astro.currentLocale ?? DEFAULT_LOCALE) as Locale;
   const t = useTranslations(locale);
   ---
   <h2>{t("filosofia.title")}</h2>
   ```
4. If the string appears in a Page-Component context (the shareable rendering used by `src/components/pages/XxxPage.astro`), pass `locale` as a prop instead.

That's it — no other wiring needed.

## Adding a new content collection per locale

Every new translatable collection follows the same recipe:

```ts
// src/content.config.ts
const newCollection = defineCollection({
  loader: glob({ pattern: "{es,en,ca}.json", base: "./src/content/<name>" }),
  schema: z.object({
    title: z.string(),
    // … fields …
  }),
});

export const collections = { /* … */, newCollection };
```

```yml
# public/admin/config.yml
- name: "new_collection"
  files:
    - { name: "es", label: "Colección · Español", file: "src/content/<name>/es.json", fields: [...] }
    - { name: "en", label: "Colección · English", file: "src/content/<name>/en.json", fields: [...] }
    - { name: "ca", label: "Colección · Català",  file: "src/content/<name>/ca.json", fields: [...] }
```

And the corresponding `getEntry("new_collection", locale)` call from each page-component.

## Adding a fourth locale

1. Add the code to `astro.config.mjs` (`i18n.locales = ["es", "en", "ca", "de"]`).
2. Add `de.json` to `src/i18n/`. Mirror every key from `es.json`; translate idiomatically.
3. For each per-locale collection, create a `de.json` (or per-slug `de/*.md`) entry in `src/content/<collection>/`. The Zod loader picks them up automatically.
4. Create page-component thin wrappers under `src/pages/de/` mirroring the existing locale folders.
5. Update the switcher in `TopBar.astro` to include the new `de` option.

Done. The build will regenerate all 4×N pages with the new locale fully wired.

## Gotchas

- **Astro 7 does not auto-duplicate pages per locale in static builds** — you need explicit page files per locale. The locale wrappers exist precisely for that reason; do not collapse them into `getStaticPaths` with `[locale]` params, because then every URL gets prefixed (including the default) and you lose `/sobre`.
- **Tattoos share slugs across locales**, so the `glob` loader would emit duplicate IDs. The content config uses a custom `generateId` (`/es/ouroboros-descent`, etc.). Do not remove it.
- **Localised title & description** build the `<title>` via the page component (so about/FAQ/reserva each translate their own `<title>` suffix). The default title lives under `site_meta.default_title` and is reused by `Layout.astro` when the page does not pass one.
- **The language switcher dropdown** depends on `<details>`-style hover and renders for any locale. Do not hide the switcher on detail pages — translators and editors rely on it to jump between translations of the same content.
